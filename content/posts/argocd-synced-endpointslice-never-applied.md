I wanted a WLED LED controller on my LAN behind the cluster's Traefik, so it would get a real TLS certificate and sit behind SSO like everything else. The controller isn't a pod. It's a little ESP32 at a fixed IP. The textbook way to point a Kubernetes Service at something outside the cluster is a Service with no selector, plus an EndpointSlice you write yourself:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: wled
spec:
  type: ClusterIP
  ports:
  - name: http
    port: 80
    targetPort: 80
---
apiVersion: discovery.k8s.io/v1
kind: EndpointSlice
metadata:
  name: wled
  labels:
    kubernetes.io/service-name: wled
addressType: IPv4
ports:
- name: http
  port: 80
  protocol: TCP
endpoints:
- addresses:
  - 192.168.1.153
```

I pushed it. ArgoCD picked up the new app directory and reported it **Synced** and **Healthy**. The page returned:

```
no available server
```

That's Traefik's 503 for a Service with no endpoints behind it. And there weren't any:

```
$ kubectl -n wled get endpointslice
No resources found in wled namespace.
```

The YAML was in Git, `kustomize build` rendered it, and ArgoCD said the app matched Git. The object didn't exist.

## ArgoCD doesn't manage Endpoints at all

ArgoCD's default `argocd-cm` ships a `resource.exclusions` list, and the first entry is this:

```yaml
### Network resources created by the Kubernetes control plane and excluded to
### reduce the number of watched events and UI clutter
- apiGroups:
  - ''
  - discovery.k8s.io
  kinds:
  - Endpoints
  - EndpointSlice
```

The reasoning makes sense. Almost every Endpoints and EndpointSlice object in a cluster is generated by the control plane from a Service's selector and changes every time a pod moves. Watching them all is a lot of events for nothing.

An exclusion doesn't mean "apply this but don't track it", though. ArgoCD drops excluded kinds from its view of the cluster *and* from the desired state it builds from Git. A hand-written EndpointSlice in your manifests just disappears before the diff. Nothing is out of sync because, as far as ArgoCD can tell, there's nothing there to compare. No warning, no "skipped" status, nothing in the resource tree.

I'd been reading **Synced** as "everything in my `kustomize build` exists in the cluster." What it actually means is "everything ArgoCD is willing to manage matches."

## Five more that only worked by accident

If the EndpointSlice was never applied, how did the other apps on this cluster that use the same pattern work? I had a handful of Services pointing at a Mac Studio on the LAN that serves LLMs and image generation:

```
$ grep -rl 'kind: Endpoints' environments/
environments/.../apps/comfyui/endpoints.yaml
environments/.../apps/fooocus/endpoints.yaml
environments/.../apps/immich-pet-tagger/endpoints.yaml
environments/.../apps/stable-diffusion/endpoints.yaml
environments/.../apps/ollama/endpoints.yaml
```

All five have live Endpoints objects in the cluster:

```
endpoints/comfyui             192.168.1.50:8188    251d
endpoints/fooocus             192.168.1.50:7865    249d
endpoints/stable-diffusion    192.168.1.50:7860    251d
endpoints/ollama              192.168.1.50:11434   293d
endpoints/immich-pet-tagger   192.168.1.50:2287    151d
```

They were created months ago by someone running `kubectl apply` on the directory by hand, which was me. ArgoCD has never touched them and never will. They survive because nothing has deleted those namespaces. If one ever gets recreated, the app comes back Synced and Healthy and serves 503s, exactly like WLED did.

Git says one thing, and the cluster happens to agree only because of a manual step nobody wrote down. That's the failure GitOps is supposed to rule out.

## Two ways out

**Override the exclusions.** You can set your own `resource.exclusions` in `argocd-cm` and leave Endpoints off it. But the setting replaces the default list rather than adding to it, so you'd have to copy the roughly 50 lines of upstream defaults (Leases, TokenReviews, CertificateSigningRequests and so on) and keep that copy in step with every ArgoCD upgrade. I'd rather not keep that copy.

**Don't use Endpoints.** A Service of `type: ExternalName` points somewhere outside the cluster with no second object:

```yaml
# The WLED controller lives outside the cluster. ExternalName rather than a
# selectorless Service + EndpointSlice, because ArgoCD excludes EndpointSlices.
apiVersion: v1
kind: Service
metadata:
  name: wled
spec:
  type: ExternalName
  externalName: 192.168.1.153
  ports:
  - name: http
    protocol: TCP
    port: 80
    targetPort: 80
```

Traefik won't route to ExternalName Services by default. It's one flag on its Kubernetes Ingress provider:

```yaml
providers:
  kubernetesIngress:
    allowExternalNameServices: true
```

With that in place the commit was a net deletion: drop `endpointslice.yaml`, change two lines in the Service. The page loaded on the next sync.

## How to check your own cluster

Search your repo for hand-written Endpoints:

```bash
grep -rlE 'kind: (Endpoints|EndpointSlice)$' .
```

Then check whether ArgoCD actually knows about them. Excluded kinds don't show up in the app's resource tree, so if the grep finds something and the ArgoCD UI doesn't show it, you have the same gap. Whatever is in the cluster got there some other way.

## Caveats

- **ExternalName with an IP is bending the spec.** `externalName` is meant to be a DNS name. CoreDNS answers an in-cluster lookup of the Service with a CNAME to the literal string `192.168.1.153`, which ordinary DNS clients won't resolve. That's fine for my case, because Traefik reads the field directly and nothing in the cluster calls the Service by name. If pods need to reach the device through the Service name, give the device a DNS name and point at that instead.
- **The five legacy apps still use hand-applied Endpoints.** I haven't moved them over yet. They work today and will keep working until something deletes their namespaces.
- **`v1 Endpoints` is deprecated anyway** as of Kubernetes 1.33, and `kubectl` prints a warning every time you list them. That's another reason to move away from the pattern, even without ArgoCD in the picture.
